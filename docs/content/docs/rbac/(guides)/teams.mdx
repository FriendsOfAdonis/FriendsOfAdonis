In a multi-tenant application, the permissions of a user depend on the team they act in. A user can be an admin in one team and a writer in another. The permission definition and the roles are shared. What changes is which roles each membership holds.

You model this with a `TeamMember` model that holds the roles, instead of the `User` model. Any Lucid model can hold roles, either [in code](/docs/rbac/roles) with `withRoles` or [in the database](/docs/rbac/roles#store-roles-in-the-database) with `withRoleModel`. Pick one of the two options below.

## Option 1: roles in code

### Create the table

The `team_members` table stores one row per user and team, with the role names of the membership in a JSON `roles` column:

```ts title="database/migrations/xxxx_create_team_members_table.ts"
import { BaseSchema } from "@adonisjs/lucid/schema";

export default class extends BaseSchema {
  protected tableName = "team_members";

  async up() {
    this.schema.createTable(this.tableName, (table) => {
      table.increments("id");
      table.integer("team_id").unsigned().notNullable().references("id").inTable("teams").onDelete("CASCADE");
      table.integer("user_id").unsigned().notNullable().references("id").inTable("users").onDelete("CASCADE");
      table.json("roles").nullable();
      table.unique(["team_id", "user_id"]);
      table.timestamp("created_at");
      table.timestamp("updated_at");
    });
  }

  async down() {
    this.schema.dropTable(this.tableName);
  }
}
```

### Create the TeamMember model

Apply `withRoles` with the roles from `start/rbac.ts`. The mixin registers the `roles` column itself.

```ts title="app/models/team_member.ts"
import { compose } from "@adonisjs/core/helpers";
import { BaseModel, column } from "@adonisjs/lucid/orm";
import { withRoles } from "@foadonis/rbac";
import { roles } from "#start/rbac";

export default class TeamMember extends compose(BaseModel, withRoles(roles)) {
  @column({ isPrimary: true })
  declare id: number;

  @column()
  declare teamId: number;

  @column()
  declare userId: number;
}
```

### Assign roles per team

When a user joins a team, create the membership and assign its roles by name.

```ts
import TeamMember from "#models/team_member";

const inTeamA = await TeamMember.create({ teamId: teamA.id, userId: user.id });
await inTeamA.assignRole("writer");

const inTeamB = await TeamMember.create({ teamId: teamB.id, userId: user.id });
await inTeamB.assignRole("admin");
```

The same user is a writer in team A and an admin in team B.

## Option 2: roles in the database

Use this option when admins edit roles at runtime. It assumes the `roles` table and the `Role` model from the [Roles](/docs/rbac/roles#store-roles-in-the-database) guide.

### Create the tables

Create the `team_members` table as in option 1, without the `roles` column. Then link memberships to roles with a `team_member_roles` pivot table:

```ts title="database/migrations/xxxx_create_team_member_roles_table.ts"
import { BaseSchema } from "@adonisjs/lucid/schema";

export default class extends BaseSchema {
  protected tableName = "team_member_roles";

  async up() {
    this.schema.createTable(this.tableName, (table) => {
      table.increments("id");
      table
        .integer("team_member_id")
        .unsigned()
        .notNullable()
        .references("id")
        .inTable("team_members")
        .onDelete("CASCADE");
      table.integer("role_id").unsigned().notNullable().references("id").inTable("roles").onDelete("CASCADE");
      table.unique(["team_member_id", "role_id"]);
    });
  }

  async down() {
    this.schema.dropTable(this.tableName);
  }
}
```

### Create the TeamMember model

Apply `withRoleModel` with the team pivot table. Set `pivotForeignKey`, because the column is `team_member_id`. Set `pivotRelatedForeignKey` too if your role column is not `role_id`.

```ts title="app/models/team_member.ts"
import { compose } from "@adonisjs/core/helpers";
import { BaseModel, column } from "@adonisjs/lucid/orm";
import { withRoleModel } from "@foadonis/rbac";
import { permissions } from "#start/rbac";
import Role from "#models/role";

export default class TeamMember extends compose(
  BaseModel,
  withRoleModel(permissions, {
    role: () => Role,
    pivotTable: "team_member_roles",
    pivotForeignKey: "team_member_id",
  })
) {
  @column({ isPrimary: true })
  declare id: number;

  @column()
  declare teamId: number;

  @column()
  declare userId: number;
}
```

### Assign roles per team

```ts
import Role from "#models/role";
import TeamMember from "#models/team_member";

const writer = await Role.findByOrFail("name", "writer");
const admin = await Role.findByOrFail("name", "admin");

const inTeamA = await TeamMember.create({ teamId: teamA.id, userId: user.id });
await inTeamA.assignRole(writer);

const inTeamB = await TeamMember.create({ teamId: teamB.id, userId: user.id });
await inTeamB.assignRole(admin);
```

## Authorize against the team member

Both options authorize the same way. `ctx.bouncer` checks the authenticated user. For a team action, load the membership and create a Bouncer instance for it. Create the abilities once, outside the controller class.

```ts title="app/controllers/team_articles_controller.ts"
import { Bouncer } from "@adonisjs/bouncer";
import type { HttpContext } from "@adonisjs/core/http";
import TeamMember from "#models/team_member";
import { permissions } from "#start/rbac";

const permissionAbilities = permissions.abilities();

export default class TeamArticlesController {
  async store({ auth, params }: HttpContext) {
    const user = auth.getUserOrFail();

    const member = await TeamMember.query()
      .where("teamId", params.teamId)
      .where("userId", user.id)
      .firstOrFail();

    const bouncer = new Bouncer(member, permissionAbilities);
    await bouncer.authorize("article.create");

    // The member can create articles in this team
  }
}
```

A user who is not a member of the team gets a 404 from `firstOrFail`. A member without the permission gets a 403.

## Scope team checks to a token

Pass the token abilities as the second argument, as you would on `ctx.bouncer`:

```ts
const user = auth.getUserOrFail();
const tokenAbilities = user.currentAccessToken?.abilities;

const bouncer = new Bouncer(member, permissionAbilities);
await bouncer.authorize("article.create", tokenAbilities);
```

The check passes when the roles of the member grant the permission and the token allows it.
